# 14 — Feedback Engine

> **TL;DR.** Five-layer feedback (band → criterion → sentence → word → phoneme). One unified data model (`feedback_artifacts`) plus presentation rules per skill. Generated by a chain of LLM calls + linguistic analysers, gated by confidence, surfaced as an interactive results page. Drives the Learning Roadmap. Nothing the user sees is free-form prose; every paragraph is templated and grounded in extracted features.

---

## 1. Why a layered engine

A single "you scored 7.0" is useless. A 9-page essay of advice is unread. The engine produces **five layers** that the user can drill into:

| Layer | What | Example |
|---|---|---|
| L1 — band | overall + per-skill numbers | "Overall 7.0" |
| L2 — criterion | per-IELTS-criterion narrative + sub-band | "Coherence 6.5: paragraphs lack topic sentences" |
| L3 — sentence | per-sentence annotations on writing | red underline: "subject-verb disagreement" |
| L4 — word | per-word vocabulary suggestions | "→ try `comprehensive`" with CEFR badge |
| L5 — phoneme | per-phoneme pronunciation scores (speaking) | `/ð/` 0.42 → tongue placement |

Each layer is independently togglable in the UI. Users on the Free plan see L1 + a teaser of L2; Starter sees L1–L2; Pro sees all five.

## 3. Per-layer specifications

### 3.1 Layer 1 — Band

The numbers. Coming from `scoring_results.band` per skill + `attempt.overall_band` derived in [`13-skills-deep.md`](13-skills-deep.md) §5.2.

UI: hero ring (animated 0→value), per-skill mini-bands, comparison vs target band (if user set one).

Internationalisation: only the labels (`O'qish` / `Reading`); numbers are universal.

### 3.2 Layer 2 — Criterion

For Writing and Speaking. Produced by the same Gemini call that yields the L1 band (`WritingScore.feedback_uz/en`, `SpeakingScore.feedback_uz/en`).

```json
{
  "criterion": "coherence_cohesion",
  "band": 6.5,
  "summary_uz": "Paragraphlar mantiqiy tartibda, lekin topic sentence kuchsiz.",
  "summary_en": "Paragraphs follow a logical order, but topic sentences are weak.",
  "evidence_quotes": [
    "Although there are many people…",   // line 4
    "Furthermore, in addition…"          // line 17
  ],
  "next_step_uz": "Har paragraf birinchi gapida asosiy fikrni aniq bayon eting.",
  "next_step_en": "State the main idea clearly in the first sentence of each paragraph."
}
```

For Reading and Listening (objective skills), L2 is derived from per-question-type accuracy:
- "Detail-oriented questions: 8/10"
- "Inference questions: 4/8"
- "Matching: 6/6"

This pivots automatically into the Roadmap ([`15-learning-roadmap.md`](15-learning-roadmap.md)).

### 3.3 Layer 3 — Sentence (writing)

Each writing essay is post-processed by **`analyse_writing` arq job** (runs after `score_writing`):

```python
# services/feedback/sentence.py
async def analyse_essay(text: str) -> list[SentenceAnnotation]:
    # 1. Sentence-split with spaCy (or Stanza).
    # 2. For each sentence: dependency parse + grammar-check via languagepro_textanalysis (see 20-).
    # 3. Map detected issues to error_taxonomy codes.
    # 4. Single Gemini call ranks sentences for severity + drafts a per-sentence rewrite.
    # 5. Persist as feedback_artifacts(layer='sentence').
```

Schema:

```json
{
  "sentence_index": 7,
  "text": "Many of people prefer to live in city.",
  "char_range": [240, 278],
  "issues": [
    { "code": "grammar.partitive_of", "span": [5, 13], "severity": "major" },
    { "code": "grammar.article_missing", "span": [33, 38], "severity": "minor" }
  ],
  "suggested_rewrite_uz": "\"Ko'p odamlar shaharda yashashni afzal ko'radi\" — 'Many people' va 'in the city'.",
  "suggested_rewrite_en": "Many people prefer to live in the city."
}
```

UI: each sentence in the essay rendered with `<mark>` spans coloured by severity. Hover → popover with the issue + suggested rewrite. Filter chips at the top: `Grammar | Lexis | Cohesion | Style`.

### 3.4 Layer 4 — Word (writing + speaking)

Two parts:

**(a) Vocabulary diversity**: per-essay/per-transcript metrics (TTR, MTLD), CEFR coverage histogram (e.g. "Your vocabulary is 70% A1-B1, 20% B2, 10% C1 — push toward B2").

**(b) Word upgrade suggestions**: each weak / overused / off-register word annotated.

```json
{
  "word": "good",
  "occurrences": [
    {"sentence_index": 3, "char_range": [20, 24]},
    {"sentence_index": 11, "char_range": [5, 9]}
  ],
  "suggestions": [
    { "lemma": "beneficial", "cefr": "B2", "context": "for academic essay" },
    { "lemma": "advantageous", "cefr": "C1" }
  ],
  "rationale_uz": "\"good\" so'zi A1 darajada — yuqori ball uchun aniqroq sinonim ishlating.",
  "rationale_en": "\"good\" is A1 — use a more precise synonym for higher band."
}
```

Source: a Gemini call seeded with the user's text + the CEFR-J + EVP word lists (loaded as a resource). The call produces ranked synonyms with CEFR tags.

UI: a tab next to the essay called "Vocabulary upgrades" lists the top-15 weak words with one-click "swap" preview.

### 3.5 Layer 5 — Phoneme (speaking)

Pipeline: see [`19-audio-analysis-pipeline.md`](19-audio-analysis-pipeline.md) for full method.

- Phoneme alignment via forced alignment (Montreal Forced Aligner self-host or wav2vec2 CTC).
- Goodness-of-Pronunciation (GOP) per phoneme: log-posterior ratio against canonical phoneme.
- Cluster errors by L1 interference patterns (Uzbek L1 → notable issues with /θ/ /ð/ /ʌ/ /æ/ — pre-curated list).

Stored as:

```json
{
  "word": "thought",
  "word_index": 14,
  "phonemes": [
    { "p": "θ", "gop": 0.32, "verdict": "needs_work" },
    { "p": "ɔː", "gop": 0.81, "verdict": "good" },
    { "p": "t", "gop": 0.94, "verdict": "good" }
  ],
  "issue_codes": ["pronunciation.consonant_th_unvoiced"],
  "rationale_uz": "/θ/ tovushini chiqarishda til tishlar orasida bo'lishi kerak — \"thanks\", \"three\" so'zlarini mashq qiling."
}
```

UI: transcript with each word coloured (green/yellow/red) by its mean GOP. Click → phoneme breakdown + recorded clip + reference (Gemini TTS playing the canonical pronunciation).

## 4. Generation pipeline (the chain)

```
attempt finished
   ↓
[1] Per-response sync layer:
    - mcq/match → grade objective; emit L2 stat for "detail/inference/matching"
    - writing → enqueue score_writing  (L1 + L2)
    - speaking → enqueue score_speaking (L1 + L2)
   ↓ (writing-specific async chain after score_writing lands)
[2] enqueue analyse_writing
    - sentence-level (L3)
    - vocab metrics + word upgrades (L4)
   ↓ (speaking-specific async chain after score_speaking lands)
[3] enqueue analyse_speaking
    - phoneme alignment + GOP (L5)
    - fluency / pause / pitch (L4-ish; surfaced as "delivery")
   ↓
[4] enqueue compile_attempt_feedback(attempt_id)
    - aggregates all artefacts → final scoring_results + band
    - calls compose_overview prompt → narrative summary
    - emits SSE 'feedback_done' to subscribed client
   ↓
[5] enqueue generate_roadmap(attempt_id)
    - see 15-learning-roadmap.md
```

Each step is an arq job; each writes to `feedback_artifacts`. SSE on `/v1/attempts/{id}/scoring/events` gives the user fine-grained progress (`band_ready`, `sentence_analysis_ready`, `phoneme_analysis_ready`, `roadmap_ready`).

---

## 5. Confidence gating

Each L2 artefact has `confidence ∈ [0,1]`. Rules:

| `confidence` | Action |
|---|---|
| ≥ 0.7 AND criteria spread ≤ 1.5 | finalised, served to user |
| < 0.7 OR spread > 1.5 | sent to `human_review_queue`; user sees provisional band with a "Under review by a human examiner" badge (Pro+ guarantee 24h SLA) |

For L3 (sentence) and L5 (phoneme) the gating is per-annotation: low-confidence issues hidden from user, retained for analytics.

---

## 6. Internationalisation

Every layer carries `_uz` and `_en` fields side-by-side, generated in **the same** Gemini call (single prompt asks for both). Switching locale in UI swaps without a network round-trip.

A Russian variant (`_ru`) is queued for Phase 5.

---

## 7. Privacy & retention

- Layer 5 phoneme-level data is the most sensitive (voice biometric proxy). Stored 90 days only; can be exported via GDPR data request and purged on account delete.
- Layer 3 may quote portions of the user's essay; we redact PII (names, addresses) via a regex + Gemini PII-detection pass before persisting.

## 9. Acceptance

- [ ] An essay graded at 7.0 produces ≥ 1 sentence annotation per paragraph and ≥ 5 word-upgrade suggestions.
- [ ] A 90-second speaking response produces ≥ 1 phoneme issue per word with mean GOP < 0.5.
- [ ] All artefacts have both `_uz` and `_en` populated.
- [ ] Switching the UI locale changes layer text instantly without a network call.
- [ ] Free user sees only L1 + a teaser; Pro user sees all 5 layers.
- [ ] Pearson r between L1 overall band and a human grader on a 30-attempt set ≥ 0.75.
- [ ] PII (names, emails, phone numbers) does not appear in any persisted feedback string.
