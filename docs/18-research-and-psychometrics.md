## 2. Multi-jury statistics

For every juror's vote (`approve / reject / borderline`):

- **Pairwise Cohen's κ** between juror pairs (3 pairs).
- **Fleiss κ** for the 3-rater agreement.
- **Krippendorff's α** (preferred for ordinal data with `borderline`).
- Per-jury **false-positive rate** (questions juror approved that human reviewer later rejected).

Stored: `analytics.jury_metrics_daily(date, juror_pair, n, cohen_kappa, ci_low, ci_high)` — refreshed nightly.

Endpoint: `GET /data/v1/research/jury-stats?from=&to=` returns the time series.

Target (acceptance): pairwise κ ≥ 0.6 (substantial agreement) on a 200-question gold set.

## 3. IRT calibration (advanced)

### 3.1 Models supported

| Model | Use |
|---|---|
| 2PL | default for MCQ |
| 3PL | with fixed `c` per item type (4-option MCQ → 0.25; cloze → 0) |
| **Multi-dimensional 2PL** (M2PL) | per-skill latent traits (4 dimensions: L/R/W/S) for cross-skill calibration |
| Testlet (`bifactor`) | reading passages — children share a passage-level random effect |
| GPCM (Generalized Partial Credit) | for partial-credit items (writing rubric criteria) |

Implemented in `python/languagepro_irt/` extending `py-irt`.

### 3.2 Calibration job

`recalibrate_items` (arq cron, nightly 03:00 UTC):

1. For each item with ≥ 30 new responses since last run:
   - Pull `(user_id, item_id, was_correct, theta_at_answer)` from `analytics.item_response_data`.
   - Run MML (Marginal Maximum Likelihood) estimation.
   - Persist updated `(a, b, c)` to `data_engine.questions` + history row to `data_engine.item_parameters_history`.
2. Compute item fit statistics: **Infit** + **Outfit** mean-square (target 0.7–1.3).
3. Items with poor fit → flag for review (`status = 'needs_review_misfit'`).
4. Run **DIF detection** (§4) weekly Sunday 04:00 UTC.

### 3.3 Cold-start `b` validation (Bobomurod's research artefact)

For each item that crosses 30 responses, log:

- `b_cold` (LLM-rated, mapped from 1–9 scale)
- `b_empirical` (post-MML)
- `n_responses`

Aggregate analysis: Pearson r and RMSE between cold and empirical `b`. Plot scatter + 45° line. **Target r ≥ 0.5**, RMSE ≤ 1.0 logits.

Endpoint: `GET /data/v1/research/calibration/cold-start-correlation?bank_id=&period=`.

### 3.4 Person-fit statistics

For each user, compute `lz` (standardised log-likelihood). Outliers (|lz| > 2.5) flag potentially problematic attempts (random clicking, copy/paste, distress). Used for cleaning the calibration corpus.

## 4. Differential Item Functioning (DIF)

Detects items that behave differently across demographic groups, holding ability constant.

### 4.1 Method

**Mantel-Haenszel** for binary items + **logistic regression DIF** as cross-check.

Groups for v1: `(uz_l1, ru_l1)` based on `users.l1` self-report (collected at signup; optional). Future: gender, age bucket.

Pseudocode:

```python
# scripts/eval/research/dif_mh.py
for item_id in approved_items:
    df = load_responses(item_id)
    df = df.merge(users[["id","l1"]], left_on="user_id", right_on="id")
    df["theta_bin"] = pd.cut(df.theta_at_answer, bins=10)
    table = df.pivot_table(values="was_correct", index="theta_bin",
                           columns="l1", aggfunc=["sum","count"])
    mh = mantel_haenszel(table)
    if mh.p_value < 0.01 / n_items:    # Bonferroni
        flag(item_id, dif_size=mh.effect_size)
```

### 4.2 Action

Flagged items move to `status = 'needs_review_dif'`. Examiner reviews and either edits or retires. Whole-bank DIF rate is a published metric.

Endpoint: `GET /data/v1/research/dif?bank_id=&group=`.

## 5. Inter-rater reliability + criterion validity

### 5.1 IRR study (each release of writing/speaking grader)

- Sample: 30 writing essays + 30 speaking responses from real attempts (anonymised).
- Raters: our LLM grader + 2 BSU instructor experts (paid ~$50 each).
- Metrics: Pearson r, quadratic-weighted Cohen's κ, MAE per criterion.
- Target: **r ≥ 0.75**, κ ≥ 0.65, MAE ≤ 0.7.

Stored in `analytics.irr_studies(study_id, model_version, n, r, kappa, mae, ci, conducted_at)`.

Reproducible: `scripts/eval/research/irr_study.py --essays 30` produces a CSV + a Markdown report.

### 5.2 Criterion validity (longitudinal)

For users who took an official IELTS exam after using LangPro:

- Optional in-app form: "Did you take an official IELTS? What was your score?" (incentivised: free 1 month Pro).
- Compare LangPro's last predicted band vs official band.
- Target: prediction within ±0.5 in 70% of cases.

This is a **slow** signal (months to accumulate), but the most defensible criterion validity.

## 6. Experiment harness (prompt A/B testing)

### 6.1 Why

Every prompt change should be evaluated, not vibe-checked. The harness lets us run two prompt versions on identical inputs and quantify the effect.

### 6.2 Mechanics

`data_engine.experiments` table:

| col | type |
|---|---|
| id | UUID PK |
| name | TEXT |
| purpose | TEXT (e.g. `score_writing`) |
| variant_a_prompt_id | TEXT |
| variant_b_prompt_id | TEXT |
| traffic_split | NUMERIC (0..1, fraction to B) |
| status | TEXT (`draft \| running \| stopped`) |
| created_at, ended_at | TIMESTAMPTZ |
| primary_metric | TEXT (`approval_rate`, `irr_pearson_r`, `cost_per_item`, ...) |
| min_sample_size | INT |

When `running`, every relevant LLM call rolls a hash(call_id) % bucket → A or B → records `experiment_id, variant` in `analytics.llm_calls`.

### 6.3 Significance testing

Once `n` per variant ≥ `min_sample_size`:

- Bootstrap confidence intervals on the primary metric (10 000 resamples).
- Two-sided permutation test for the diff.
- Surface results in `/admin/experiments/{id}` with the recommendation: "Adopt B (p < 0.001, +0.04 absolute on approval rate)".

A second `secondary_metrics` array tracks cost, latency, false-positive rate.

### 6.4 Endpoints

| Method | Path | Purpose |
|---|---|---|
| POST | `/data/v1/experiments` | superadmin |
| PATCH | `/data/v1/experiments/{id}` | start / stop |
| GET | `/data/v1/experiments/{id}/results` | metrics + CI |
| GET | `/data/v1/experiments` | list |

## 7. RAG over the question bank

A scientific tool for content authors: "show me 10 published items most similar to this passage so I avoid duplicates and find related ones."

### 7.1 Implementation

Already covered by `data_engine.question_embeddings` (pgvector HNSW). Endpoint: `GET /data/v1/banks/{id}/similar?to=<question_id>&k=10`.

### 7.2 Use in generation (Phase 3)

Retrieval-Augmented Generation: the generator prompt includes 3 in-bank examples retrieved by topic embedding. Improves style consistency. Side effect: potential duplicate risk → dedup pass remains mandatory.

A/B candidate experiment: with-retrieval vs without-retrieval on `approval_rate` and `irr_alignment`.

## 8. Roadmap calibration (cross-link to [`15-`](15-learning-roadmap.md))

The roadmap predicts a band; we measure how often the prediction was right.

`analytics.roadmap_calibration_mat`:
- Group users by predicted P50 bucket (e.g. 6.0, 6.5, 7.0).
- For each bucket, compute the fraction whose actual band landed within ±0.5.
- Plot as a calibration curve. Target ECE ≤ 0.05.

This is **research output**: weekly recomputation, surfaced on `/admin/research/calibration`. The dissertation can compare calibration across cohort-similarity values of `K`.

## 12. Acceptance

- [ ] Pairwise Cohen's κ on a 200-question gold set is ≥ 0.6.
- [ ] After 30 responses per item, mean |Δb| from cold-start is ≥ 0.1; Pearson r(b_cold, b_empirical) ≥ 0.5.
- [ ] DIF analysis surfaces at least 1 item with significant DIF on a synthetic dataset where DIF was injected (validation test).
- [ ] LLM ↔ human Pearson r ≥ 0.75 on writing IRR study (n=30).
- [ ] `experiments/{id}/results` returns p-value + bootstrap CI within 30s of a 1000-call experiment.
- [ ] `scripts/eval/research/export_dataset.py` produces a parquet readable by `pandas` and `arrow` without errors.
- [ ] Each research notebook in `docs/research/` runs end-to-end on the latest dataset export.
