# ADR DE-0003 — IRT 2PL with fixed `c` (vs 3PL)

- **Status**: Accepted
- **Date**: 2026-04-26

## Context
IRT model selection for item calibration.

| Model | Params | Data needed | Pros | Cons |
|---|---|---|---|---|
| 1PL (Rasch) | b only | low | Stable, simple | Assumes equal discrimination |
| **2PL** | a, b | medium (~30 resp/item) | Discrimination realistic | More params to estimate |
| 3PL | a, b, c | high (≥100 resp/item) | Accounts for guessing | Overfits in low-data regime |

## Decision
**2PL** with `c` fixed by question type:
- 4-option MCQ: `c = 0.25`
- Cloze / completion: `c = 0`
- True/False/NG: `c = 0.33`

This is "constrained 3PL" — gets guessing benefits without 3PL's data hunger.

## Implementation
- `py-irt` library, model `2pl`
- `c` not estimated; injected as constant in Fisher info formula
- Recalibration trigger: every 30 new responses per item
- Min responses per item before any update: 30

## Consequences
- ~30 responses suffices for first calibration (vs 100+ for 3PL)
- Discrimination `a` adapts per item (e.g., poorly-written distractors lower `a`)
- Defensible: c-fixed approach cited in Hambleton & Swaminathan (1985)
